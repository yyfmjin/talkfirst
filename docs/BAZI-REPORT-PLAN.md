# 起名完整报告（付费）· 方案存档

> 状态：**未开工**。2026-11-08 只做了可行性核对，产品决定"保留创意，后续再说"。
> 原始需求来自运营方给的《起名完整报告开发提示词》文档（8 条功能提示词 + 验收清单）。
> 本文只记"要做成什么样、代码现状如何、还缺什么"，避免下次从零重读。

## 1. 产品形态（运营方的四条规矩）

1. **免费版一样都不砍**：6 个名字、简要解释、换一批、指定姓氏与风格、每日运势当天。
2. **收费只卖「完整报告」这个成品**：深度解析、英文故事、备选字库、长图/PDF。
3. **不弹窗、不倒计时、不逼单**；入口只在结果页底部一处。
4. 对外口径一律「传统文化娱乐 · 性格参考」，不出现算命、改运、转运、旺财。

七章内容：命盘摘要卡 / 名字总览榜 / 逐名深度解析 / 英文名字故事 / 备选字库 /
长图与 PDF 导出 / 一次免费重出。

## 2. 对照代码的结论（`/opt/bazi`，2026-11-08 核对）

| 章节 | 结论 | 依据 |
|---|---|---|
| 目录预览 | 纯前端 | 结果页已有位置 |
| 摘要卡 + 总览榜 | 数据齐 | `generateChineseNames()` 返回 `basis` 与 6 个 `names`（score / elementSummary / meaningSummary） |
| 逐名深度解析 | 大部分可用 | 每字有 `c/py/tone/el/strokes/meaning/blessing/styles`；`wuge{tian,ren,di,wai,zong,lucky}` 已带逐格吉凶 |
| 英文故事 | 有底子，需人工定稿 | 字库自带英文字义与 blessing |
| 备选字库 | 字库偏小 | 全站手工字库 **80 字**（五行各约 16），挑 20 个可行，但"每组 4–5 个"要补字 |
| 长图 / PDF | **需新依赖** | 现在只有浏览器端 canvas 分享卡（`share-card.tsx`，750×1080），服务端无渲染能力 |
| 解锁 / 购买 | 可做 | 起名确定性 + `batch` 0–50，可作解锁键；库里没有订单/解锁表，需新增迁移 |

两个字段必须按规矩降级：
- **没有「出处/典故」字段** → 只写字义，不现编典故（与运营方要求一致）。
- **没有谐音/重名数据** → 只能是规则提醒 + 固定收尾句「正式使用前请中文朋友把关谐音」。

另一个容易漏的点：**访客也能起名**（`guestNames` 动作，档案只存 localStorage），
所以"访客解锁只存本机"与现有访客逻辑一致，但换设备/清缓存即失效。

## 3. 三个硬门槛（不是代码问题）

1. **支付资质**：微信 H5 支付要「已备案域名 + 商户号 + API 证书」；
   支付宝要签约产品；Stripe 要海外主体 + 可达 webhook。
   `talkfirst.ccwu.cc` 的备案状态未确认 —— 未确认前只做「测试开关 + 解锁流程」。
2. **长图 / PDF 放哪**：
   - A（推荐）：长图沿用现有 canvas 在端上画，PDF 走浏览器打印 → 零新依赖；
   - B：容器加 headless Chrome + 中文字体 → 镜像 +300MB，还要清临时文件。
3. **"一个人的命盘"指谁**：登录用户的 `profiles`，还是"人物档案" `candidates`
   （给朋友排盘）？决定解锁键是否要带 `candidateId`。

## 4. 待拍板

- [ ] 域名备案 / 商户号有没有
- [ ] 长图/PDF 走端上还是服务端
- [ ] 报告只支持本人命盘，还是也支持候选人
- [ ] 访客报告"换设备就没了"是否在页面写明
- [ ] 失败退款口径（没接支付前先写"重试 / 联系客服补发"）
- [ ] 字库是否补到每行 24 字（否则备选字库这章很薄）

## 5. 建议的落地顺序

1. 目录 + 摘要卡 + 总览榜（免费部分先上线，先把"报告页"立住）
2. 备选字库（顺带补字）
3. 英文故事（先出 6 段英文给运营方过目）
4. 长图 / PDF（按拍板方案）
5. 解锁 + 假付费开关（真支付等资质）
6. 定价文案（9.9 元 / $6.9，集中在配置项）

估时：1–3 约 1 天；4–5 半天；6 取决于方案（端上半天 / 服务端 1.5 天起）；7 解锁流程半天，支付另算。

## 6. 硬约束（开工时逐条守）

- 不动免费功能，不改现有配色/框架，不引新前端框架
- 不碰 `app.db` 已有数据（解锁表是新增）
- 密钥只走环境变量，代码里不出现
- 不写死价格（集中一处），不出现"限时/原价"这类对比价
- 报告数据只从现有命盘与字库取，不编字义、不编典故
